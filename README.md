# Container Sorter

打开容器按R堆叠背包同物品到容器。

*A one-key QoL mod for The Long Dark 2.55: sort the duplicate items in your backpack into the container you have open.*

## 它解决什么问题

游戏自带的容器操作只有两种：一件一件地搬，或者「全部转移」把背包整个倒进去。前者枯燥，后者会把你没打算放下的东西也塞进柜子。

这个 mod 走第三条路：**只搬「这个容器里已经有的那些种类」**。你已经决定某类东西归这个柜子，剩下的重复部分就交给它按容器剩余容量一趟搬完——背包里其它东西原封不动，柜子原有的分类习惯也不会被打乱。

## 功能

- **一键整理** —— 只在容器面板打开时生效，键位可自由重绑定（默认 `R`）
- **按容量装** —— 每件都看容器当前剩余容量，装满即止；一堆东西整组太大时会按份拆开，只搬装得下的那一部分，直到连单个都塞不进去为止
- **自动并堆** —— 背包里的 20 根木柴搬进已有 1 根的那堆后，容器里只有一堆 21 根，而不是两堆（液体、新鲜度相差过大的食物不并，保持原版习惯）
- **目标数量** —— 清单里写 `GEAR_Arrow*20`，按键后背包里就是 20 支箭：多了把多出来的塞进柜子，少了从柜子里取回来，不用自己算差额
- **忽略清单** —— `Mods/ContainerSorterIgnore.txt` 里列出的物品可以「一个都不搬」或「背包留 N 个、其余搬走」，改完存盘即生效，不用重启游戏
- **保留哪一份说了算** —— 需要留一个时，背包留耐久最差的那件、好的收进容器；耐久一样则留更轻的那份（同样新鲜的肉，1kg 的进柜子、半公斤的留在包里）
- **即时刷新** —— 搬完界面当场更新，两边负重条同时变化，不用关掉面板再打开

## 安装

**前置条件**

- 《The Long Dark》Steam / Epic 版，游戏版本 **2.55**（本 mod 针对 2.55 编译）
- [MelonLoader](https://melonwiki.xyz/) **0.6.0 或更高**（开发与实测环境为 0.7.3）
- **ModSettings**（作者 Digitalzombie / zeobviouslyfakeacc，可在 Nexus 或 TLD 模组社区获取）—— 设置页与按键重绑定依赖它，**必须安装**

**步骤**

1. 确认游戏目录下已有 `MelonLoader/` 文件夹（没有就先装 MelonLoader 并启动一次游戏）
2. 确认 `Mods/` 里已有 `ModSettings.dll`
3. 把 `ContainerSorter.dll` 复制到 `TheLongDark/Mods/`
4. 重启游戏

默认安装路径参考：

```
F:\SteamLibrary\steamapps\common\TheLongDark\Mods\ContainerSorter.dll
```

## 卸载

删掉 `TheLongDark/Mods/ContainerSorter.dll` 即可。`Mods/ContainerSorter.json`（设置）与 `Mods/ContainerSorterIgnore.txt`（忽略清单）可以留着下次再用，也可以一并删除；已经搬进柜子的物品不受影响。

## 使用

1. 打开任意容器（柜子、冰箱、工具箱、尸体……）
2. 按**整理键**（默认 `R`）
3. 背包里与该容器**重复的种类**会按剩余容量搬进去，清单里标了目标数量的种类会先补齐再搬；日志会给出这次两边各动了多少：

```
[CONTAINER_Fridge] 容量 30kg，已用 4.2kg，剩余 25.8kg
整理完成：放入 3 件（2.4kg），其中 1 件并进已有堆叠，容器剩余 23.4kg
```

```
目标数量：从容器取回 20 份（1 种）
[CONTAINER_Locker] 容量 40kg，已用 12kg，剩余 28kg，已从容器取回 20 份（1 种）补足目标数量
整理完成：放入 0 件（0kg），从容器取回 20 份（1 种），容器剩余 26kg
```

键位、是否要按住 Ctrl、以及下面这些行为开关，都在 **选项 → Mod Settings → Container Sorter** 里。

**会被跳过的东西**：穿戴中的衣物、手上拿着的物品、随身小包（satchel）里的物品，以及水分/燃料这类玩家看不到的内部供给。前三项可以在设置里关掉。

## 忽略清单

第一次启动时会自动生成 `Mods/ContainerSorterIgnore.txt`（内容全是注释，默认不忽略任何东西）。文件按「分区」组织，每行一个物品 ID（游戏内部 prefab 名）：

```
#全部无视/Ignore All
GEAR_Revolver
GEAR_Arrow

#保留（至少一个）/Keep At Least One
GEAR_Hacksaw
GEAR_HeavyBandage*4
GEAR_OldMansBeardDressing*2
```

| 写法                                  | 含义                                |
| ----------------------------------- | --------------------------------- |
| `#全部无视/Ignore All` 之后的条目            | 这些物品一个都不搬                         |
| `#保留（至少一个）/Keep At Least One` 之后的条目 | 背包留 1 个，其余搬进容器（只出不进）              |
| `GEAR_HeavyBandage*4`               | 目标数量 4 份：多了搬进容器，少了从容器取回            |
| `GEAR_Hacksaw`（不带数字）                | 老行为：背包至少留 1 个，只往外搬，不会去容器里拿        |

### 目标数量（`物品ID*数字`）

带数字的条目按「背包里保持 N 份」处理，按键时两个方向都会走：

- **背包比 N 多** —— 多出来的部分搬进容器，背包剩 N 份
- **背包比 N 少** —— 从容器取回差额，背包补到 N 份（容器里有多少取多少，不够就只补到能补的数量）
- **刚好 N 份** —— 什么都不动

几点说明：

- 份数按堆叠累计：背包里 20 支一堆 + 3 支一堆，算 23 份
- 容器里没有这种物品时不会凭空变出来，只按老样子往下搬
- 这个数字统计的是背包里的实际数量，包括穿在身上、拿在手里、装在小背包里的份数；但设置里勾了跳过的那几类不会被搬动，所以它们占用的份额没法再调整
- 只有 `物品ID*数字` 会这样双向处理；不带数字的条目、以及分区标记里的数字仍然是「只出不进」的老行为

几点通用说明：

- **份数分隔符是 `*`（星号），不是 `#`** —— `#` 是注释符号，写成 `GEAR_X#4` 会被当成注释，结果按分区默认处理（日志里会提醒）
- 全角 `＊` 也能识别；`*` 后面必须是纯数字，`GEAR_X*abc`、`GEAR_X*4张` 这种会当备注丢掉，条目退回分区默认行为
- 每行一个 prefab 名，`#` 或 `//` 开头是注释，行尾也可以跟注释；大小写不敏感，`GEAR_` 前缀可省略（`Acorn*5` 等价 `GEAR_Acorn*5`）
- 分区可以写多段，后面的覆盖前面的；第一个标记之前的条目按「全部无视」处理
- 「保留」对非堆叠物品（工具类）同样有效：背包里同种有好几把时留一把，其余搬进容器；非堆叠物品的目标数量就是「留几把」
- **改完存盘就生效**，下次按整理键自动重读，不用重启游戏

想查某个物品的 prefab 名：把「输出详细日志」打开，日志里会打印实际搬运 / 跳过的名字，抄进清单即可。

## 设置

| 项             | 说明                                    | 默认  |
| ------------- | ------------------------------------- | --- |
| 整理键           | 点一下设置项，再按下想绑的键（键盘/鼠标键都行）              | `R` |
| 需要同时按住 Ctrl   | 防和其它 mod 抢键                           | 关   |
| 合并可堆叠物品       | 关掉则每件单独落一堆                            | 开   |
| 跳过穿戴中/手持物品    | 关掉等于强制脱装备                             | 开   |
| 跳过小背包里的物品     | 小包内的东西不迁移                             | 开   |
| 启用忽略清单        | 关掉则 `ContainerSorterIgnore.txt` 完全不生效 | 开   |
| 保留时优先把高耐久放进容器 | 留耐久最低的那件，好的收进容器                       | 开   |
| 耐久相同时优先搬更重的   | 留单份更轻的那份（肉类：先搬 1kg 的块）                | 开   |
| 输出详细日志        | 逐件打印迁移明细，排查问题用                        | 关   |

## 兼容性

- 只在**容器面板打开**时响应按键，其它时候按键没有任何副作用
- 不修改物品定义、堆叠规则或容器容量，只在触发瞬间做搬运；与改背包 / 改堆叠数值的 mod 无已知冲突（未做系统性组合测试）
- 匹配依据是物品的 prefab 名，所以 `RUINED` 状态、被 mod 改过名字后缀的物品照样算同一种
- 若游戏切到新版 Input System 独占导致读不到键盘，热键会自动停用并在日志里说明，而不是每帧报错

## 常见问题

**按了没反应？**  
确认容器面板是打开的；如果设置里开了「需要同时按住 Ctrl」，要按 `Ctrl + 整理键`。键位也可能被别的 mod 占用，换一个试试。

**东西没搬？**  
本 mod 只搬「容器里已经有的种类」。柜子里一件都没有时按了也不会有反应——想从零开始装柜子，用游戏自带的转移。

**搬了一半就停了？**  
容器满了。整组放不下时它会尽量塞到塞不下单个为止，剩下的留在背包。

**写了 `物品ID*数字`，数量还是没到目标？**  
先看容器里有没有这种物品——没有就不会去取；再看是否够数，不够时只会补到「容器里有多少」为止，日志里会写「N 种仍不够」。另外穿在身上、拿在手里的那份算进目标数量，但设置里勾了跳过的物品不会被搬动。

**没有并成一堆？**  
液体（按体积记账）、新鲜度相差太大的食物不会并堆；另外当某类物品的数量变化不反映到重量上时，它会退回「单独放一堆」，而不是冒险算错容量。

**日志里出现「已退回背包」？**  
原版对容器容量的判定比本 mod 更严（或该容器不接受这个分类），物品会安全退回背包，不会丢东西。
